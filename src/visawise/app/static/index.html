Each row is one controlled config — same dataset, model, prompt, corpus and judge, differing by a single variable — so any two can be compared cleanly. All 52 questions scored. The two rerank→4 · 8B runs are one identical config run twice: they differ by ~0.03 on the judged metrics, which is the noise floor — and why the reranker's +0.04 MRR (a judge-free retrieval metric) is the result to trust here.

Reranking does two things at once. We measured them apart.

Reranking — reorder

rerank→8 vs no rerank: the same 8 passages, reordered by a cross-encoder. Hit-rate is identical (nothing new retrieved), but MRR climbs 0.798 → 0.838. The reranker earns its place by ranking the right passage higher — cleanly, with no judge in the loop.

Reranking — truncate

rerank→4 vs rerank→8: keeping only the top 4 passages instead of 8 is what nudges hit-rate down (0.885 → 0.865) — that, not the reranking, is the recall cost. In exchange: higher context precision and half the input tokens, so a free 8B model answers in ~4s.

The uncontrolled version of this comparison couldn't tell these three effects apart. The controlled ladder can — and it changes what "reranking helps" means.

We re-tested our own 2024 finding. It didn't hold.

2024 · research corpus

0.44 → 0.83 faithfulness, vector vs hybrid. A chasm — the finding this project was built on.

2026 · fresh corpus, same weights

0.908 vs 0.945 (vector vs hybrid, neither reranked) — both strong, the chasm gone. Cleaner extraction lifted vector-only. Hybrid still wins ranking (MRR 0.798 vs 0.777), so it still serves.

A harness that can only confirm what you already believe isn't a harness. This one gets to disagree with its own origin story.
